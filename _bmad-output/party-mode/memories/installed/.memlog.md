- (decision) Berthold entscheidet: Release 1 = einfacher Ein-Klick-Tisch (Schnellpfad). Release 2 = Chat-Conversation-System (A2UI/CopilotKit) MUSS first-class sein, kein Anhängsel — architektonisch von Anfang an mitgedacht, auch wenn UI erst in R2 kommt.
- (dynamic) Berthold hebt die Latte: Chat-System (A2UI/AG-UI/CopilotKit/ADK) soll nicht nur first-class parallel existieren, sondern langfristig von Nutzern gegenüber Formular-Klickerei BEVORZUGT werden. Amelias Recherche entwarnte Interop-Sorgen (CopilotKit ist A2UI-Launchpartner), Reifegrad-Risiko v0.9 bleibt als Randnotiz.
- (decision) Klarstellung: Chat 'gewinnt' nicht gegen den Ein-Klick-Schnellpfad — der bleibt few-click, ohne Chat, unangetastet. Chat ist ein vollwertiger PARALLELER Conversation-Flow, der langfristig beides kann (einfache + komplexe Buchungen), ausgerollt in zwei Stufen: erst Buchungen, dann FM-Verwaltung. Winstons Idee generativer UI-Komponenten im Chat (Karten, Kalender, Klick-Karten statt Fließtext) wurde bestätigt.
- (outcome) Session beendet mit klarem Release-Schnitt für Desk4Me: R1=Schnellpfad/Explorationspfad+Winstons 3 Architektur-Bedingungen (benannte Operationen, stabile Bezeichner, strukturierte Fehlerantworten); R2a=Chat-Buchung parallel (nicht ersetzend) mit generativer UI (A2UI/AG-UI/CopilotKit+ADK, Interop bestätigt, v0.9-Reifegradrisiko notiert); R2b=Chat für FM-Verwaltung. 'Chat bevorzugt' als Erfolgskriterium auf später vertagt, nicht Release-1-Anforderung. Weiter mit bmad-prd.

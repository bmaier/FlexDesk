Please update the existing Desk4Me design with the following changes. These are refinements and additions to what's already built — integrate them into the current screens and flows rather than starting over or replacing existing layouts.

Terminology used below: Liegenschaft (site), Gebäude (building), Raum (room), Desk (a single bookable workspace), Meetingraum (meeting room), Präferenz (a saved preference used to rank desks).

1. **Room/floor-plan visualization when browsing/picking a desk.** Wherever a user browses down to a specific room to choose a desk, show a spatial, floor-plan-style view of that room's desks instead of a plain list. This needs to work in two situations, and should feel visually consistent between them:
   - When a real floor plan (Grundriss) has been uploaded for that room: overlay the desks on top of that actual floor plan image, positioned where they really sit.
   - When no floor plan image exists for a room: still render the desks in a visual, spatial layout (an abstracted/schematic room outline with desks arranged in it) rather than falling back to a plain list — it should read as "a room with desks in it," not a table of rows, even without a real floor plan behind it.
   - Clicking or hovering a desk on this view reveals its properties (equipment/labels) in a side panel.
   - Desks that strongly match the current employee's saved Präferenz should be visually highlighted directly on this view (e.g. a distinct fill color or glow), so the best matches are immediately scannable among many desks. Carry the same highlight treatment into any quick-booking list view, for consistency.

2. **Request-and-approval booking for certain rooms.** Some rooms (mainly Meetingräume) can be marked as requiring approval. For these specific rooms, booking no longer confirms instantly — it creates a pending request instead, shown to the requester as a clear "angefragt, wartet auf Genehmigung" (requested, awaiting approval) state rather than a normal confirmation. Add an approver-side view: a simple inbox-style list of pending requests for the rooms the current viewer is responsible for (as the room's assigned owner or as facility management), each with a one-click approve/reject action. In the requester's own bookings list, a pending request should appear with a visually distinct card/state from confirmed bookings.

3. **Keep this distinct from the existing confidential-room-blocking flow.** The approval-required flow in point 2 is functionally different from the confidential/VS-NFD room-blocking flow you already have: the confidential flow has no approver step at all — its only safeguard is the deliberate friction of being a separate, unmissable flow. Please make sure these two remain visually and functionally distinct so a user can't confuse "requires approval" with "confidential block."

4. **Facility management additions.** In the room management/admin view: add a way to mark a room with a clear, structural "erfordert Genehmigung" (requires approval) property — this should read as a hard, structural property of the room (like its room number), not mixed in with the flexible equipment/label tags — plus a field to assign one or more people as that room's Raumverantwortlicher (owner/approver). Also add a facility-management action that can cancel ANY booking, including ones already firmly confirmed, for any reason at all — style its confirmation step with a warning tone (since it overrides a real commitment), visually distinct from a routine, low-stakes cancel action.
